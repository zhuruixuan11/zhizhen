# 知识入库与数量核验

更新于 2026-11-05，说明以 `backend/app/scripts/init_knowledge.py`、`core/milvus_client.py` 和 `core/llm.py` 为准。

## 入库流程

1. `neo4j-init` 执行 `python -m app.scripts.init_knowledge`，读取挂载的 `/init/knowledge_graph.cypher`。
2. 删除整行注释、按分号拆分 Cypher，执行种子语句向 Neo4j 写入节点和关系。
3. 从 Neo4j 读取 `Formula`、`Syndrome`、`Symptom`、`Herb` 四类节点，拼接名称、功效、定义、主症等文本。
4. 通过配置的 Embedding 服务将每个节点文本转换成一个向量，写入 Milvus `tcm_knowledge`。
5. 创建 `IVF_FLAT` 索引，以 `IP` 为相似度度量，加载集合供检索。

当前是结构化图谱种子入库，不是上传 PDF/Word 后自动分块的文档知识库。`Effect`、`Meridian`、`Contraindication` 参与图谱，但不在当前向量化标签列表中。

管理员可通过 `POST /api/v1/admin/graph/import` 触发完整导入，通过 `POST /api/v1/admin/graph/vector-rebuild` 触发向量生成；任务由 Celery 执行，需检查返回任务的状态与 worker 日志。

## 数量与幂等边界

每个目标节点每次成功向量化写入一行。数据库实际数量取决于种子版本、历史写入次数和模型调用是否成功，不能把某次运行的统计写成固定容量。

Neo4j 种子使用 `MERGE`。Milvus 方法虽然名为 `upsert_vectors`，实际使用自增主键和 `insert`，没有按 `(label,node_id)` 去重；重复初始化或“向量重建”会追加行。当前该操作不是幂等重建，也不会先清空旧集合。不要仅为了重启应用反复运行知识初始化。

未配置模型、Milvus 不可用、某类 Embedding 失败可能导致跳过向量写入。脚本退出码主要反映 Cypher 导入是否成功，必须同时检查 `vectors` 和各类错误日志。更换模型或维度前需规划集合迁移，已有集合不会自动改变维度。

`embed_texts` 每个请求最多发送 10 条文本，同一次函数调用按批串行。这里的 **10 是单请求文本条数，不是全系统并发上限**；多个 API/worker 调用间尚无统一并发限流器。

## 只读统计

在 Neo4j Browser（`http://localhost:7474`）登录后分别执行：

```cypher
MATCH (n) RETURN labels(n) AS labels, count(*) AS count ORDER BY count DESC;
MATCH ()-[r]->() RETURN type(r) AS relation, count(*) AS count ORDER BY count DESC;
MATCH (n) WHERE n:Formula OR n:Syndrome OR n:Symptom OR n:Herb
RETURN count(n) AS expected_vectors_per_complete_run;
```

关系统计为有向边计数；双向存储的不相容关系计为两条边。图谱管理员统计接口为 `GET /api/v1/admin/graph/stats`。

在项目根目录运行以下只读 Milvus 统计；不会触发知识导入：

```powershell
docker compose exec backend python -c "from app.core.milvus_client import _connect, COLLECTION_NAME; from pymilvus import Collection, utility; _connect(); print({'collection': COLLECTION_NAME, 'rows': Collection(COLLECTION_NAME).num_entities} if utility.has_collection(COLLECTION_NAME) else {'collection': COLLECTION_NAME, 'exists': False})"
```

`num_entities` 是集合行数统计，不代表唯一知识节点数；核验重复需进一步分页读取 `label,node_id` 并去重，不宜一次拉取大集合。本文更新未重查运行数据库，也未清理已有重复向量。

## 检索实现

图检索与向量检索结果被合并、去重后送入辨证链路；当前未实现按倒数排名加权的 RRF 算法。图谱引用用于报告溯源，但知识覆盖和检索命中不等于临床结论必然正确，最终报告仍需医生审核。
