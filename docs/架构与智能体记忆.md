# 企业化架构与运行说明

按当前代码核对，更新于 2026-11-05。MySQL 存储业务数据，Neo4j/Milvus 负责检索，Redis/Celery 处理任务；PostgreSQL 是智能体记忆的权威存储。

## 智能体边界

采用确定性编排的三个专职智能体，不引入无限循环的自主协商：

| 角色 | 绑定工具 | 数量 |
| --- | --- | --- |
| inquiry 追问 | load_memory、save_memory、extract_symptoms、ask | 4 |
| syndrome 辨证 | embed、retrieve、differentiate | 3 |
| care 调养 | recommend | 1 |

工具粒度围绕业务能力，调养智能体只消费检索结果，单个工具足够，不为凑数量增加访问权限。
图像识别保持异步能力，不另设常驻智能体；输入/输出安全检查由编排强制执行。
编排基于 LangChain/LangGraph 1.x 的 StateGraph：syndrome→care 复合成 diagnosis 图，retrieve/differentiate/recommend 三节点共享状态（槽位/图检索依据/结构化输出在节点间传递），图无环、有界。各节点内部工具调用统一经 `BoundedToolExecutor`：每个 agent 各自声明工具白名单与独立调用预算（默认 16 次，`settings.agent_max_tool_calls`），未绑定工具抛 `PermissionError`、未登记工具抛 `ValueError`、预算耗尽抛 `RuntimeError`；模型重试另由 LLM_MAX_RETRIES 限制。inquiry 追问保留 token 级 SSE 流式并复用 `BoundedToolExecutor` 的有界语义。
这是有边界的角色工作流，不是让模型任意选择 Python 函数的 ReAct agent。

预算按 `BoundedToolExecutor` 实例计数，不是整个会话或整张图的全局预算；同一角色在不同节点新建执行器时分别计数。LangChain 使用 `ChatOpenAI` / `OpenAIEmbeddings`，图像识别经 worker 异步执行。LangGraph 当前不配置 checkpointer，PostgreSQL 保存的是业务记忆，不是 LangGraph 图执行断点。

## PostgreSQL 记忆

- 短期：tenant/user/session 作用域下保存结构化槽位，默认 24 小时，跨 API 重启恢复。
- 长期：tenant/user 作用域下保存用户明确确认的事实，默认 365 天；不自动固化模型诊断。
- 正文使用现有 AES-GCM 字段加密能力；ENCRYPTION_KEY 必须备份、统一配置，轮换需离线重加密。
- 读取排除过期记录；memory-beat 每小时触发 Celery 清理，每批最多 10000 条。
- 每个用户最多 20 条长期记忆，每条输入 2000 字符；内部写入限制 32 KiB。
- 同一会话使用 PostgreSQL 事务级 advisory lock，忙时返回 SSE session_busy；断开释放锁。
- PostgreSQL 不可用时返回明确失败，不静默退化为丢失记忆；readyz 包含数据库与表检查。
- MySQL 消息和 PostgreSQL 状态没有跨库事务；失败重试可能重复消息。需业务幂等键/outbox 后才能承诺 exactly-once。

API 均要求 Bearer 登录，owner 来自认证信息：

```http
GET /api/v1/memory
GET /api/v1/memory/suggestions?session_id=9
PUT /api/v1/memory
Content-Type: application/json

{"key":"preference","content":"希望使用简短的中文回答","consent":true}

DELETE /api/v1/memory/preference
```

长期事实作为背景输入追问，不直接作为当前症状或诊断。短期记忆过期后，主动生成报告分支可从最近 100 条消息中的助手槽位快照恢复；普通追问分支未实现同样的恢复逻辑。没有 Redis 旧槽位的自动迁移。

### 前端录入与自动整理

个人中心 `/profile` 和报告页面均已接入 `MemoryPanel`，支持新增、编辑、删除、查看到期时间和核实候选记忆。保存健康画像后刷新候选；报告页按当前问诊整理。

`memory_service.collect_candidates` 使用确定性规则提取过敏史、既往病史、长期用药，不把模型证型、当前症状自动写成长期事实。健康画像优先于问诊快照；未指定会话时最多读取最近 20 次问诊，每次最多读取最近 100 条助手记录，取最近一个槽位快照。

相同内容不重复提议，已有不同内容显示替换提示。“核实并保存”后仍需明确勾选同意，接口要求 `consent: true`；没有后台自动同意或自动落库。“暂不保存”仅在当前页面隐藏，刷新后可能再次出现。手动记忆支持用户自行填写其他背景事实。

单次问诊删除只清除对应短期记忆，已确认长期记忆保留；个人中心“清除我的健康数据”清除该用户全部长短期记忆并保留账号，详见 [删除范围](医患双端与人工接诊.md#历史问诊与删除)。

## 可观测性

- OpenTelemetry：HTTP → agent/tool → LLM HTTP / SQLAlchemy(MySQL/PostgreSQL) / Redis，以及 Celery 消息上下文传播；默认父级采样 + 10% 根请求采样。
- Jaeger：OTLP gRPC 接收，UI 本机 16686；Grafana 已配置 Jaeger 数据源。
- structlog：统一 stdlib 与结构化 JSON 日志，包含 trace_id/span_id；HTTP 返回 X-Trace-Id。
- Prometheus：路由模板标签避免高基数，统计完整 SSE 时长、500、LLM 成败、token、agent/tool 时延及 SSE 业务错误。
- Grafana：修复 prometheus 数据源 UID，加入工具调用/P95/SSE 失败面板。
- LangSmith：LANGSMITH_TRACING=true 且设置 API key 才启用；隐藏输入输出，metadata 包含 otel_trace_id 和 scene，可跨平台查找；当前追踪 LangChain 模型调用，不把 HTTP trace 自动等同于 LangSmith run ID。
- API 默认一个 Uvicorn 进程以保证 Prometheus 抓取一致；增加 API 副本必须配置独立抓取/服务发现与网关。
- Celery worker 的 Prometheus 进程内指标未单独导出，任务追踪通过 Jaeger 查看。日志输出 stdout，长期集中检索还需接入日志存储。

## 启动与验证

1. 合并 `.env.example` 新增项到已有 `.env`，不要覆盖已有密钥。
2. 生产设置 APP_ENV=production，配置独立 JWT_SECRET_KEY、ENCRYPTION_KEY、ADMIN_PASSWORD 和 CORS_ORIGINS JSON 数组。
3. `docker compose up -d --build`：memory-migrate 显式执行幂等建表；API/worker 等迁移成功后启动。
4. 已有数据库手动迁移：`docker compose run --rm memory-migrate`。
5. `docker compose logs backend worker`；访问 `/readyz`、`/metrics`，Grafana 3000、Jaeger 16686。
6. 独立测试：

```powershell
docker build -t tcm/backend:enterprise-test ./backend
docker compose -f docker-compose.test.yml up --abort-on-container-exit --exit-code-from tests
docker compose -f docker-compose.test.yml down
```

集成测试仅在独立临时 PostgreSQL 上运行；不要把 RUN_POSTGRES_TESTS=1 指向业务数据库，测试会清空 agent_memory。

## 生产交付边界

当前 Compose 是单机部署基线。正式上线仍需针对部署环境完成 TLS/密钥管理、PostgreSQL 备份与恢复演练、容量与压测、镜像漏洞扫描/锁定 digest、数据库最小权限、告警通知路由。
现有 S3Mock 为测试对象存储，Jaeger all-in-one 为内存追踪存储，不能作为高可用持久化生产方案。需替换为正式 S3 服务及持久化 Jaeger 后端。
长期记忆前端已接通，但自动整理仅生成待确认建议，尚无持久化的候选拒绝记录。删除业务数据未覆盖上传文件实体、异步任务载荷和备份，不能据此宣称已完成全部存储介质的数据擦除。`DATA_RETENTION_DAYS` 配置尚未接通所有健康业务表的定时清理；当前定时任务只清理到期智能体记忆。
