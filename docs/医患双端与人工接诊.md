# 医患双端与人工接诊

按当前代码核对，更新于 2026-11-05。患者登录 `/login`，医生登录 `/doctor/login`，管理员登录 `/admin/login`。登录入口与账号角色必须对应。

患者入口 `/patient`，医生入口 `/doctor`，管理员医生账号入口 `/admin/doctors`。普通注册只创建 USER；医生由同租户管理员核验资质后创建。

患者在问诊页面选择医生并明确授权本次问诊资料。接诊状态为 requested → active → closed。患者可撤回访问授权（cancelled），撤回后医生不可再读取，可重新选择医生授权。

## 报告先审后发

正常追问由模型返回 `ready=true` 时进入报告生成；用户发送“生成报告”等命令也会进入生成分支，不再把该命令作为症状答案继续追问。若已有分析则返回现有审核状态。输入安全检查仍优先执行。未配置模型或追问解析失败时，当前回退逻辑以主诉和寒热槽位作为就绪条件，这不是完整的临床信息充分性判断。

追问以分轮收集为目标，优先性别和年龄，每次一两项；前端根据问题提供选项，允许补充文字。已获得的舌象/面色识别结果参与分析；图片识别失败与缺少照片不同，应先查看任务状态和 worker 日志。

报告结构包含：证型、置信度、辨证依据、鉴别分析、调治原则、方剂参考、饮食/穴位/生活建议、风险级别、急症标志、免责声明及图谱引用。字段允许为空，不承诺每份报告都有全部内容；患者获得的是医生确认的快照。

生成报告后仅保存 AI 原始分析及独立的 report_review 草稿，会话变为 pending_review。已授权医生的工作台每 10 秒刷新待审核标记；尚未授权医生的患者可在报告页选择医生。没有医生账号时需管理员先开通，草稿不会自动发布。

医生接受接诊后可修改辨证结论、依据、建议等，保存草稿不会对患者公开。点击“确认并发布给患者”后，系统冻结该版本、记录医生和确认时间、写入医患消息，会话完成。患者报告页每 5 秒检查审核状态并展示医生确认的报告。通知是站内消息和页面轮询，不发送短信或邮件。

患者报告接口及 SSE 只返回待审核状态或确认后的快照；历史 result 消息不再返回 AI 正文。旧报告未自动视为已审核，医生需保存并确认一次。重复点击生成报告返回现有审核状态，避免重复生成；后续补充问诊生成新版本时需重新审核。保存和发布校验报告编号、草稿修订号、指定医生与授权状态，防止旧页面覆盖新报告。已发布快照不可直接修改，原始 AI 报告保留。

部署时运行 `python -m app.scripts.migrate_clinical` 创建新增审核表，再启动新版 backend。迁移不删除现有报告或问诊记录。

医生只能查看同租户、指定给自己且未撤回授权的病例；接诊后双方可发消息，医生可提交独立于 AI 报告的审阅意见，提交后才能结束接诊。消息每 5 秒刷新，离开页面停止轮询。医生列表目前最多返回最新 200 条病例。

MySQL 新增 clinical_encounter、clinical_message，并已回写 init/01_schema.sql 主 DDL（BIGINT 主键/外键与 entities.py 对齐）；Compose 的 clinical-migrate 执行带数据库锁的幂等建表，backend 等待成功。迁移不修改或清空既有问诊表。接诊操作和医生病例读取写入操作审计。

医生工作台同步展示问诊会话内已上传的舌象/面色图像：病例详情返回 `images`（含 image_id、image_type、quality_pass 质检状态、analysis_result 识别结果），图像文件经 `GET /clinical/sessions/{session_id}/images/{image_id}` 端点输出。权限经 `encounter()` 限定为 DOCTOR 角色指定医生或患者本人，跨租户/未授权病例不可读取。

## 历史问诊与删除

患者中心 `/patient` 和历史问诊 `/history` 展示“问诊记录与报告”，支持按编号/主诉检索、按报告状态筛选，提供继续问诊、查看报告及红色“删除”按钮。当前接口最多加载最近 100 次问诊，前端每页 8 条；统计值是已加载数据的数量。

| 操作 | 接口 | 删除范围 | 保留内容 |
| --- | --- | --- | --- |
| 删除单次问诊 | `DELETE /api/v1/consultation/{session_id}` | 本次消息、图像数据库记录、分析与审核报告、接诊与医患消息、相关本人反馈及本次短期记忆 | 账号、其他问诊、健康画像、已确认长期记忆 |
| 清除我的健康数据 | `DELETE /api/v1/auth/me/data` | 本人健康画像、问诊及关联业务记录、反馈、全部长短期记忆 | 账号、密码、角色和登录能力 |
| 删除长期记忆 | `DELETE /api/v1/memory/{key}` | 指定记忆 | 账号和问诊记录 |

两种健康数据删除均需前端确认。单次删除校验用户及租户归属，越权/不存在返回 404，问诊正在处理返回 409，成功返回 204 并刷新列表；当前没有“只删除报告但保留问诊”的独立按钮。

删除会话后，医生端关联病例和报告也随业务级联删除。安全审计保留元数据、清空对应健康原文，另记录删除操作。当前未同步删除上传目录中的实际图片、异步任务参数/结果或历史备份；MySQL 与 PostgreSQL 未使用跨库原子事务，失败可能需要检查两边状态。不要把接口成功解释成所有副本已物理擦除。

## 实现说明

- 图像上传固定 kombu==5.4.2 以兼容 redis==5.2.1；backend/worker 共用 uploads-data，worker 只读。队列投递失败将任务置为 failed 并返回 503。
- AI 问诊调用模型原生 stream，逐步提取 JSON reply 展示；槽位不暴露，部分输出后失败不拼接另一个模型回复。最终辨证报告完成安全检查后进入医生审核，不直接返回正文。前端 assistant 使用 reactive 实时刷新。
- 知识库新增症状详情接口，修正反向关联查询和详情属性展示。

## 更新与验证

无数据库结构变化时，在项目根目录执行 `docker compose build backend frontend`，然后 `docker compose up -d --no-deps --wait --wait-timeout 120 backend worker memory-beat frontend`。依赖服务需已正常启动；迁移及完整排障步骤见 [部署与排障](部署更新与故障排查.md)。定向更新避免不必要地重跑知识初始化。

若 Docker Hub 网络不可用但已有 tcm/frontend:latest，可在 frontend 目录执行 `npm run build`，返回根目录执行：

```powershell
docker build --pull=false -f frontend/Dockerfile.prebuilt -t tcm/frontend:latest frontend
docker compose up -d --no-deps frontend
```

该离线方式复制当前构建产物和 nginx.conf。

验证包括前端类型检查和生产构建，以及后端 unittest：接诊状态流转、授权撤回、跨患者/跨租户拒绝、图片任务异常、模型流式行为、向量分批、追踪与工具预算。真实模型调用需要有效供应商配置，自动化测试不发送患者照片到模型服务。
